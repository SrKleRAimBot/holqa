Run event-driven applications: queue, object storage and schedule delivery, with local drivers as the first binding.

- `@holqa/local` (new): `createLocalEnvironment` returns a binding with SQLite-backed queues (leases, delays, retries, dead letters), filesystem object storage (metadata, `object.created`/`object.deleted` events per subscription, bounded listings, development signed URLs served by `storage.fetch`), a scheduler driven by an injectable `Clock` (`systemClock`, `ManualClock`), inspection (`messages`, `deadLetters`, `redrive`, `duplicate`, `purge`, `events`, `runs`, `trigger`) and `settle()`.
- `@holqa/runtime-bun`: delivery workers consume the binding's sources: at-least-once queue delivery with the declared backoff, `maxAttempts` and dead-lettering; immediate dead-lettering of messages that fail their schema, have an older `schemaVersion` or exceed their attempts; bounded consumer concurrency; object event delivery with `delivery.objectEvents`; scheduled runs with the `skip`/`allow` overlap policy; graceful shutdown that releases cancelled deliveries; lease renewal through `DeliverySource.extend`; messages with a newer `schemaVersion` are retried rather than dropped. New options `delivery.concurrency`, `delivery.leaseMs`, `delivery.objectEvents`; `stats().delivery`; `RuntimeDeliveryOptions`, `TransportStats`, `DeliveryStats`. Behaviour change: `createRuntime` no longer throws for queue, bucket and schedule handlers, so code that caught that error at construction must handle it at `start()`, which fails with `HOLQA_RUNTIME_START_FAILED` and one `HOLQA_BINDING_CAPABILITY_UNSUPPORTED` cause per undeliverable handler (including queues without a declared backoff on bindings that cannot delay redeliveries by the default 300 seconds); `manualTriggers: true` now only means "invoke-only". `RuntimeStats` gains a required `delivery` field, which breaks hand-built or mocked `RuntimeStats` objects. `createRuntime` rejects two consumers of one queue (`HOLQA_QUEUE_CONSUMER_DUPLICATE`). Direct `invoke` metadata is checked more strictly: object event handlers require `{ eventId, eventTime, attempt }`, a queue `schemaVersion` must be a positive integer, and a schedule `runId` must be a string and `trigger` `cron` or `manual` (these extra fields were ignored before).
- `@holqa/sdk`: new types `ObjectDeletedHandler`, `ObjectDeletedOptions`, `ObjectDeletedContext`, `DeletedObjectInfo`, `ObjectEventInfo`; `queue({ delivery: { backoff } })`; `send(message, { delaySeconds })` resolves to `{ messageId }` (it resolved to `undefined`); consumers see `delivery.schemaVersion`. Buckets gain `head`, `delete`, `list`, `signedUrl` and `onObjectDeleted`; `put` resolves to object metadata; object handlers receive `event: { id, time, attempt }`. Schedule handlers receive `trigger` and `runId`. Behaviour change: cron expressions are parsed at declaration, so extensions such as `L`, `W` and `#`, which were accepted before, now fail with `HOLQA_DECLARATION_INVALID`.
- `@holqa/core`: `RuntimeBinding.sources` and the source contracts (`DeliverySource` with optional `extend`, `LeasedDelivery`, `ReceiveRequest`, `DeliveryFailure`, `QueueSource`, `ObjectEventSource`, `ObjectEventSubscription`, `ScheduleSource`, `ScheduleListener`, `ScheduleTick`, `ScheduleSubscription`, `ScheduleRunResult` as a union of `SucceededScheduleRun`, `FailedScheduleRun` and `SkippedScheduleRun`, `ScheduleRunStatus`, `ResourceSources`); `checkTriggerDelivery`; the `holqa.object-event/1` envelope (`ObjectEvent`, `ObjectEventObject`, `objectEventFormat`, `objectEventTypes`, `readObjectEvent`); `checkObjectKey`, `maxObjectKeyBytes`; `parseCronSchedule`, `nextCronTime`, `isTimeZone`, `CronSchedule`; `backoffDelaySeconds`, `longestBackoffDelaySeconds`, `queueBackoffProblem`, `defaultQueueBackoff`; the types `QueueBackoff`, `QueueBackoffStrategy`, `FixedQueueBackoff`, `ExponentialQueueBackoff`, `QueueSendOptions`, `QueueSendReceipt`, `ObjectMetadata`, `ListObjectsOptions`, `ObjectList`, `SignedUrl`, `SignedUrlMethod`, `SignedUrlOptions`, `ObjectEventType`, `ObjectEventMetadata`, `ObjectEventTriggerOptions`, `ObjectEventTriggerSchemas`, `ScheduleRunTrigger`; queue `backoff` requirements and `backoff`/`maxDelaySeconds` capabilities; bucket `events`/`signedUrls` capabilities; the `bucket.object-deleted` trigger kind (inserted after `bucket.object-created` in `triggerKinds`). Eight new diagnostic codes: `HOLQA_OPERATION_INVALID`, `HOLQA_OBJECT_KEY_INVALID`, `HOLQA_OBJECT_NOT_FOUND`, `HOLQA_SIGNED_URL_INVALID`, `HOLQA_SCHEDULE_INVALID`, `HOLQA_LOCAL_STATE_UNSUPPORTED`, `HOLQA_DELIVERY_ATTEMPTS_EXHAUSTED`, `HOLQA_SCHEDULE_RUN_SKIPPED`; none is renamed. Breaking for binding implementers (a major change after 1.0): `QueueDriver.send(envelope, options)` receives the `holqa.message/1` envelope instead of the bare payload and must return `{ messageId }`; `BucketDriver.put` receives bytes and options and returns metadata, and `head`, `delete`, `list` and `signUrl` are required; object-created trigger metadata changed from `{}` to `{ eventId, eventTime, attempt }`. Code that maps over `TriggerKind` must handle `bucket.object-deleted`.
- `@holqa/compiler`: compiles `bucket.object-deleted` triggers and a queue's `backoff` requirement (capability `queue.backoff.<strategy>`), with the same rules as the SDK. The manifest version 1 JSON Schema accepts both; existing manifests are unchanged byte for byte, and readers built before this change reject manifests that use them. The schema's cron pattern is unchanged, so a manifest built before cron validation that uses `L`, `W` or `#` still validates and fails later, when a scheduler subscribes, with `HOLQA_SCHEDULE_INVALID`.

Examples: `examples/schema-evolution` had to change its hand-written queue driver for the new `QueueDriver.send` contract, which is the binding-implementer break described above; `examples/package-smoke` gained `@holqa/local` checks without changing existing ones.
