Event safety: static cycle analysis, event lineage, runtime execution guards, handler idempotency, controlled redrive and simulation budgets ([ADR 0026](../docs/architecture/decisions/0026-event-safety-analysis-lineage-and-execution-guards.md)).

- `@holqa/compiler`: `compileApplication` returns `events`, the event dependency graph (publications found in handler code with `known`, `potential` and `unknown` certainty, declared publications, object key prefixes) and its cycles, and reports cycles as `HOLQA_EVENT_CYCLE` warnings (known) or information (potential); justified cycles are reported as allowed. It accepts the optional `appExports` and `resolveModule` inputs. Malformed handler `events` and `idempotency` policies are `HOLQA_DECLARATION_INVALID` errors, declared publications to undeclared resources `HOLQA_RESOURCE_NOT_FOUND`. `CompileApplicationSuccess` gains a required `events`, which breaks hand-built results. `holqa inspect --json` and `holqa build --manifest --json` may now list `HOLQA_EVENT_CYCLE` in `diagnostics`. New exports: `analyzeEvents`, `checkEventPolicies`, `analyzePublications`, `buildEventGraph`, `analyzeEventCycles`, `eventCycleDiagnostics`, `describeCyclePath`, `validateEventAnalysis` and their types. The manifest is unchanged: same format, same bytes, same fingerprints. Behaviour change: applications with event cycles now compile with warnings they did not have before.
- `@holqa/runtime-bun`: every invocation has a lineage (`rootId`, `depth`, `correlationId`, `causationId`), propagated through traces; roots are always runtime-assigned. New `events` option (`maxDepth`, default 16; `maxPublications`, default 1000; `maxEventAgeMs`; `maxEventsPerOperation`, which requires a binding with `operationBudgets`). Refused publications throw `HOLQA_EVENT_DEPTH_EXCEEDED`, `HOLQA_EVENT_PUBLICATION_LIMIT_EXCEEDED` or `HOLQA_EXECUTION_BUDGET_EXCEEDED`; deliveries past a limit, or whose handler failed after a refusal, are dead-lettered or discarded at once. `start` fails with `HOLQA_BINDING_CAPABILITY_UNSUPPORTED` when a handler declares `idempotency` without an idempotency store, or `maxEventsPerOperation` is set without an operation budget store. Behaviour changes: the default depth and publication limits apply to existing applications (chains deeper than 16 events or invocations publishing more than 1000 events are now refused); guard errors and `HOLQA_IDEMPOTENCY_IN_PROGRESS` keep their code instead of becoming `HOLQA_HANDLER_FAILED`; logs gain `rootId` and `depth` unless the invocation is its own root at depth 0, and invocation logs gain `blocked`. Type changes: `InvocationOutcome` gains a required `lineage` and an optional `blocked`, and `DeliveryStats` a required `blocked` count, which breaks hand-built objects of those types; `InvocationRequest` gains optional `rootId` and `depth`, which only delivery transports set (`runtime.invoke` ignores them, so a direct invocation is always a root). A guard code thrown by application code is an ordinary failure; only this invocation's own refusals (`blocked`) end a delivery terminally. New exported types `RuntimeEventLimits`, `EventGuardViolation`.
- `@holqa/core`: `DeliveryTrace` gains optional `rootId` and `depth`, `LeasedDelivery` an optional `sentAt`, `InvocationContext` an optional `lineage`, handler definitions optional `events` and `idempotency`, and `RuntimeBinding` optional `operationBudgets` and `idempotency` stores (all additive). New `InvocationLineage`, `lineageOfDelivery`, `childTrace`, `HandlerEventPolicy`, `HandlerIdempotencyPolicy`, `eventPolicyProblems`, `idempotencyPolicyProblems`, `defaultEventLimits`, `isEventGuardCode`, `OperationBudgetStore`, `IdempotencyStore`, `createIdempotencyKey`, `createMemoryIdempotencyStore`, `maxCycleJustificationLength`, `maxIdempotencyLeaseSeconds`, `maxIdempotencyRetentionSeconds` and their types (`HandlerCycleAllowance`, `IdempotencyKeySource`, `OperationBudgetRequest`, `OperationBudgetResult`, `IdempotencyClaim`, `IdempotencyBeginOptions`, `IdempotencyCompleteOptions`, `IdempotencyExtendOptions`, `MemoryIdempotencyStoreOptions`). A trace without lineage roots at the delivery, never at its caller-chosen correlation. Seven new diagnostic codes: `HOLQA_EVENT_CYCLE`, `HOLQA_EVENT_DEPTH_EXCEEDED`, `HOLQA_EVENT_PUBLICATION_LIMIT_EXCEEDED`, `HOLQA_EVENT_AGE_EXCEEDED`, `HOLQA_EXECUTION_BUDGET_EXCEEDED`, `HOLQA_IDEMPOTENCY_IN_PROGRESS`, `HOLQA_SIMULATION_BUDGET_EXCEEDED`; none is renamed.
- `@holqa/sdk`: every handler registration accepts `events` (`publishes`, `cycle: { justification }`, `maxPublications`, `maxDepth`); queue consumers and object event handlers accept `idempotency` (`true` or `{ key?, retentionSeconds?, leaseSeconds? }`, defaults one day and 30 seconds; the claim is renewed while the handler runs); queue, object event and schedule handler contexts gain an optional `lineage`. `events.publishes` accepts queue and bucket handles only; `leaseSeconds` is at most 86 400 and `retentionSeconds` at most one year. New exported types `HandlerEventOptions`, `PublishableResource`, `IdempotencyOptions`, `QueueIdempotencyContext`, `ObjectEventIdempotencyContext`. Additive.
- `@holqa/local`: the binding provides `operationBudgets` and `idempotency`, kept in the state database and shared by every process using the directory; deliveries store and return their lineage and `sentAt`. `queues.redrive` also accepts `{ messageId?, limit?, newOperation? }` (the string form still works; a `limit` that is not a positive whole number is `HOLQA_OPERATION_INVALID`; `newOperation` also resets the send time used by `maxEventAgeMs`). `stateVersion` is now `3`. The state format is now 3: format 1 and 2 directories are upgraded in place when opened, after which earlier versions refuse them with `HOLQA_LOCAL_STATE_UNSUPPORTED`. New exported type `RedriveOptions`.
- `@holqa/testing`: `createTestApp` accepts `events` and `maxInvocations` (default 10 000; overruns throw `HOLQA_SIMULATION_BUDGET_EXCEEDED` from `flush`, `advance` and `drain`) and gains `lineage(invocationId)` and `operation(rootId)`; `redrive` accepts the local selection. `InvocationRecord` gains required `rootId` and `depth` and an optional `blocked`, which breaks hand-built records. New export `lineageOf`.
- `@holqa/cli`: `holqa inspect --cycles` prints the event graph and its cycles (text, or `{ cycles, diagnostics, events }` with `--json`; exit code `0` whenever analysis succeeds). New `holqa queue redrive <queue> [--message <id>] [--limit <n>] [--dry-run] [--new-operation]`. The analysis report carries the event analysis, which the CLI validates; `AnalysisSuccess` gains an optional `events` (additive for custom hosts; a report without it is accepted, and only `inspect --cycles` then fails with `HOLQA_ANALYSIS_FAILED`). Analysis prints a note to its output when it cannot import a module it follows. `implementedCommands` gains `queue redrive`; the help text lists `--cycles` and the new command.

Examples: the new `examples/event-safety` runs `holqa inspect --cycles` through the built CLI and the application on `createTestApp`. `examples/package-smoke` is unchanged.
