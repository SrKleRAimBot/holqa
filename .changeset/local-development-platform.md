Local development and testing platform: `holqa dev`, the operation commands, `holqa state`, `holqa doctor`, `createTestApp`, and traces across queue messages and object events.

- `@holqa/cli`: `holqa dev` supervises the application: it analyzes and builds it, runs it on the local binding in one process per generation behind a stable address, watches files, classifies each change (`implementation`, `handlers`, `resources`, `environment`), swaps generations in two phases so a failed reload (`HOLQA_RELOAD_FAILED`) keeps the previous one serving, reports contract changes with the compatibility checker, and writes JSON lines with `--json`. `holqa invoke`, `holqa queue send`, `holqa storage put`, `holqa cron run` and `holqa state` run in the session when one runs, otherwise in a process started for the operation; `holqa doctor` checks the project and the local environment. Behaviour change: these commands exited with `1` and `HOLQA_CLI_NOT_IMPLEMENTED`; only `holqa openapi generate` and `holqa build` without `--manifest` still do. `parseOptions` accepts `positionals` and returns them. `CliHost` gains the optional `readFile`, `dev`, `operate` and `doctor` members (additive). The help text lists the new commands. The build ships a new `generation.js` entry point. Further contract details: `@holqa/cli` exports the types `DevEvent` (the line format of `holqa dev --json`), `ManifestChange`, `ChangeKind`, `IdentityChanges`, `ApplicationSummary`, `HandlerSummary`, `ResourceSummary`, `LocalOperation`, `OperationResponse`, `OperateOutcome`, `OperationTarget`, `DoctorCheck`, `DevRequest`, `DoctorRequest`, `AppLocation` and `PhaseResult`; the operation commands write `{ target, ...result, output? }` and `holqa doctor` writes `{ checks, diagnostics }` to standard output, with `{"diagnostics":[...]}` on standard error on failure; `implementedCommands` gained seven entries and `proposedCommands` lost six; `parseOptions` now treats `--` as the end of options for every command, so `holqa inspect --app x --`, which exited with `2`, now runs. Sessions persist `.holqa/dev/session.json` next to the application and `dev-session.json` in the state directory (format `holqa.dev-session/1`, not a public contract).
- `@holqa/runtime-bun`: handler code's queue sends and bucket writes and deletes carry the invocation's trace to drivers, and deliveries that come back with a trace join it (`correlationId`, plus `causationId` in logs); without a trace a delivery's `correlationId` is still its message or event identifier. Log entries gain `triggerKind`, `resourceId`, `causationId` and, on finished invocations that emitted something, `emitted` (and `source` on failures). `InvocationOutcome` gains a required `emitted` list and `InvocationRequest` an optional `causationId`; hand-built `InvocationOutcome` objects must add `emitted`. `createRuntime` accepts `handlerSources`; `CompiledApplication` gains a required `handlerSources` field, which breaks hand-built `CompiledApplication` objects. New exported types `EmittedEvent`, `EmittedQueueMessage`, `EmittedObjectChange`.
- `@holqa/local`: deliveries store the sender's trace and return it as `LeasedDelivery.trace`; inspection shows it (`LocalQueueMessage.trace`, `LocalObjectEvent.trace`) and event deliveries' `visibleAt`. New `storage.objects`, `storage.retainSubscriptions`, `ManualClock.nextTimerDue` and `manualTriggerMetadata`. The state format is now 2: format 1 directories are upgraded in place when opened, after which earlier versions refuse them with `HOLQA_LOCAL_STATE_UNSUPPORTED`. `LocalStorage` gains members, which breaks custom implementations of that interface.
- `@holqa/testing`: `createTestApp` runs an application with isolated local state and a virtual clock, with `flush`, `advance`, `drain`, failure injection (`failNext`), duplicate delivery, redrive, inspection, invocation records and traces, and `dispose`. It requires Bun; the type assertions still import nothing Bun-specific, which is why `engines` still names Node only. New dependencies on `@holqa/core`, `@holqa/local` and `@holqa/runtime-bun`.
- `@holqa/core`: `DeliveryTrace`, `DriverOperationContext` (an optional last parameter of `QueueDriver.send`, `BucketDriver.put` and `BucketDriver.delete`), and `LeasedDelivery.trace`, all additive. Six new diagnostic codes: `HOLQA_RELOAD_FAILED`, `HOLQA_DEV_SESSION_ACTIVE`, `HOLQA_DEV_START_FAILED`, `HOLQA_FILE_UNREADABLE`, `HOLQA_DOCTOR_CHECK_FAILED`, `HOLQA_LOCAL_OPERATION_FAILED`; none is renamed.

Examples: the new `examples/order-pipeline` runs with `holqa dev` (`pnpm start`; it has no `dev` script, so the root `pnpm dev` still only runs the package watchers) and is tested with `createTestApp` and the built CLI. `examples/package-smoke` had to change its check of `holqa dev --json` (now implemented) to `holqa openapi generate --json`, which is the CLI behaviour change described above, and gained checks for `generation.js` and `createTestApp`.
