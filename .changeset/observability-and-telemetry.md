Observability: structured logging with levels and redaction, distributed tracing with W3C trace context, framework metrics, OTLP/HTTP export, a local telemetry store with CLI inspection, and telemetry test helpers ([ADR 0027](../docs/architecture/decisions/0027-observability-telemetry-and-local-inspection.md)).

- `@holqa/core`: new observability contracts: `TraceContext`, `parseTraceparent`, `formatTraceparent`, `isTraceId`, `isSpanId`, `randomTraceId`, `randomSpanId`, `traceparentHeader`, `tracestateHeader`; the telemetry data model (`SpanRecord`, `SpanKind`, `SpanStatus`, `SpanLink`, `SpanEvent`, `MetricRecord` and its point types, `TelemetryLogRecord`, `TelemetryResource`, `TelemetryAttributes`) and the `TelemetryExporter` interface (`TelemetryExportOptions` passes an abort signal); `frameworkMetrics` (literal metric names), `FrameworkMetric`, `metricOverflowAttribute`; `createRedactor`, `defaultSensitiveKeys`, `defaultSensitiveKeySuffixes`, `redactedValue`, `minRedactedValueLength`. `SpanStatus` is a union (`message` only with `code: "error"`); `parseTraceparent` accepts later trace context versions by their first four fields. Additive: `DeliveryTrace.traceparent`, `childTrace(lineage, invocationId, traceparent?)`, `InvocationContext.telemetry` (`InvocationTelemetry`), `QueueSource.pending`. **Type change:** `InvocationLogger` gains a required `debug` member, so hand-written logger doubles (for example an `InvocationContext` built in a test) must add it; runtime behavior is unaffected. Three new diagnostic codes: `HOLQA_TELEMETRY_CONFIG_INVALID`, `HOLQA_TELEMETRY_EXPORT_FAILED`, `HOLQA_TELEMETRY_NOT_FOUND`; none is renamed.
- `@holqa/runtime-bun`: new `RuntimeOptions.telemetry` (exporters, service name and resource, `sampleRatio`, `messages: "parent" | "link"`, `acceptTraceparent`, `exportLogs`, limits, identifier generator), `logLevel` and `redact`; `StopOptions.telemetryMs`; `Runtime.telemetry` (`enabled`, `flush`); `RuntimeStats.telemetry`. Spans for every invocation (HTTP and RPC `server`, deliveries `consumer`, scheduled runs and direct invocations `internal`) and for queue sends (`producer`) and bucket operations (`client`) from handler code, with `traceparent` propagated over HTTP and through messages and object events; framework metrics; a bounded background export pipeline that never affects invocations. Invalid telemetry settings fail `createRuntime` with `HOLQA_TELEMETRY_CONFIG_INVALID`. Behavior changes: every log entry and span is redacted (values of fields whose names contain `password`, `secret`, `token`, `authorization`, `cookie`, `apikey`, `accesskey`, `privatekey`, `credential` or `signature`, and occurrences of declared secret values), so fields with such names now log `[REDACTED]`; redaction is on for every runtime, telemetry or not, and covers the message and fields of log entries (never `level` or `time`). With telemetry enabled, log entries gain `traceId` and `spanId`. Server spans record the route template, not the request path; unknown HTTP methods are recorded as `_OTHER`. Telemetry is disabled unless exporters are given. **Type change:** `Runtime.telemetry` and `RuntimeStats.telemetry` are new required members, which breaks hand-written `Runtime` or `RuntimeStats` objects (for example mocks). New exported types `RuntimeTelemetryOptions`, `MessageTraceRelation`, `TelemetryIdGenerator`, `TelemetryStats`, `RuntimeTelemetryControl`, `PipelineLimits`.
- `@holqa/sdk`: route, procedure, middleware, queue, object event and schedule handler arguments gain an optional `telemetry` with the invocation's `traceparent`; loggers gain `debug`. Additive.
- `@holqa/local`: the state format is now 4 (`stateVersion` is `4`): deliveries store the publishing span's `traceparent`. Format 1 to 3 directories are upgraded in place when opened, after which earlier versions refuse them with `HOLQA_LOCAL_STATE_UNSUPPORTED`. Queue sources implement `pending`. `queues.redrive` with `newOperation` also clears the stored `traceparent`, so the redriven message starts a new trace. New `createLocalTelemetryStore`, `openLocalTelemetryReader`, `telemetryFileName`, `telemetryStoreVersion` (a bounded `telemetry.sqlite` store of spans, logs and metrics, separate from the state; log entries are queued and written in batches) and `readDeliveryHistory`, with their types.
- `@holqa/testing`: `createTestApp` records telemetry in memory with deterministic identifiers (`telemetry`, `flushTelemetry`) and accepts `telemetry`, `logLevel` and `redact`. Behavior change: telemetry is always on in test apps, so their log entries (and `logs`) always carry `traceId` and `spanId`. New `createMemoryTelemetry` and `spanTree`, with `MemoryTelemetry`, `SpanFilter` and `SpanNode`.
- `@holqa/cli`: new commands `holqa logs [--follow]`, `holqa traces list`, `holqa traces inspect <trace-id>`, `holqa events inspect <event-id>` and `holqa metrics` (text and `--json`; `logs --json` prints JSON lines), which read the local telemetry store and state without running the application; `implementedCommands` and the help text list them. `holqa dev`, `holqa invoke` and `holqa cron run` record telemetry in the store and export over OTLP/HTTP when `OTEL_EXPORTER_OTLP_ENDPOINT` is set; unsupported `OTEL_*` values fail the application process with `HOLQA_TELEMETRY_CONFIG_INVALID`. The dev session counts reload failures. `CliHost` gains optional `telemetry`, `deliveryHistory` and `waitForStop` (additive for custom hosts). Text output of `holqa dev` (and `holqa logs`) adds an `otel <first 8 hex digits of the trace identifier>` segment to log lines. Telemetry commands report store errors as diagnostics (exit code `1`); one-off application processes open the telemetry store only for `invoke` and `cron run`. Now depends on `@holqa/opentelemetry`.
- `@holqa/opentelemetry` (new package): `createOtlpHttpExporter` (OTLP/HTTP with JSON, Fetch API only, no retries), `readOtelEnvironment` for the standard `OTEL_*` variables (exporter settings checked only when an endpoint is configured; per-signal headers sent only to their signal through `tracesHeaders`, `metricsHeaders` and `logsHeaders`; non-parent-based samplers, compression, certificates, per-signal timeouts and propagators other than `tracecontext` rejected), and the OTLP/JSON encoders. No OpenTelemetry package is a dependency.

Examples: the new `examples/observability` covers the acceptance scenario with `createTestApp`, a runtime exporting to a stand-in OTLP/HTTP receiver (also while it is unavailable) and the built CLI. `examples/schema-evolution` adds `debug` to a hand-written logger double. `examples/package-smoke` is unchanged.
