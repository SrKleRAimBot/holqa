Make compiled applications executable, starting with HTTP routes and RPC procedures.

- `@holqa/runtime-bun` (new): `createRuntime` (one invocation dispatcher with identifiers, time limits, cancellation, bounded concurrency, error normalization and structured logs; lifecycle `start`/`stop` with graceful draining and application-scoped values; HTTP routing, CORS and `holqa.rpc/1` error envelopes), `serve` and `stopOnSignals` (`Bun.serve`), `loadCompiledApplication` (reads `holqa build --manifest` output, `HOLQA_BUILD_STALE`), `createEnvironmentBinding`, `jsonLineSink`, `silentSink`.
- `@holqa/sdk`: `api.route`, `reply(status, body, headers?)`, `api.procedure`, typed `middleware` (application, API, route and procedure scopes; `middleware.requires`), `scoped`, and `defineApp({ middleware })`. `HttpApiHandle` and `App` gain type parameters with defaults (`{}`), and `app.resources` keeps its exact type when no application middleware is declared. `HttpApiHandle` also gains required `route` and `procedure` members, so hand-built objects typed as `HttpApiHandle` no longer type-check (a major change after 1.0). Routes and procedures of an API that was never passed to `defineApp` fail with `HOLQA_DECLARATION_INVALID` when invoked.
- `@holqa/core`: `httpEndpoint`, `httpRouteKeys`, `joinRoutePath`, `routeShape`; the `http.procedure` trigger kind (appended to `triggerKinds`) and an optional `headers` schema for `http.route`; `HttpInvocationInput`, `HttpRejectedError`, `HttpErrorBody`, the `holqa.rpc/1` constants and envelope types, `ApplicationScope`, `ScopedDefinition`; optional `correlationId` and `scope` on `InvocationContext`. Fifteen new diagnostic codes (`HOLQA_HTTP_ROUTE_NOT_FOUND`, `HOLQA_HTTP_METHOD_NOT_ALLOWED`, `HOLQA_HTTP_MEDIA_TYPE_UNSUPPORTED`, `HOLQA_HTTP_REJECTED`, `HOLQA_RESPONSE_INVALID`, `HOLQA_HANDLER_FAILED`, `HOLQA_HANDLER_NOT_FOUND`, `HOLQA_INVOCATION_TIMEOUT`, `HOLQA_INVOCATION_CANCELLED`, `HOLQA_RUNTIME_OVERLOADED`, `HOLQA_RUNTIME_NOT_RUNNING`, `HOLQA_RUNTIME_START_FAILED`, `HOLQA_CONFIG_INVALID`, `HOLQA_RPC_VERSION_UNSUPPORTED`, `HOLQA_BUILD_STALE`). Additive for values; code that switches exhaustively over `TriggerKind` or maps over it (`{ [K in TriggerKind]: ... }`) must handle `http.procedure` (a major change for type consumers after 1.0).
- `@holqa/compiler`: compiles `http.procedure` triggers (operation, `input`/`output` roles) and the `headers` role of routes, and reports RPC paths that collide with routes as `HOLQA_ROUTE_CONFLICT`. Behaviour change: route conflicts are now checked across every API of an application (the rule the runtime applies, shared through `httpRouteKeys` in `@holqa/core`), so two APIs with the same base path and route no longer compile. A procedure's `output` must have a JSON-representable output side, like `response.<status>`. The manifest version 1 JSON Schema accepts the new trigger kind and roles: existing manifests are unchanged byte for byte, but readers built before this change reject manifests that use them.
