# S3-compatible object storage

> **Status:** **Implemented** in `@holqa/s3` (private, unpublished): a resource provider for the `bucket` contract version 1 and, with an event channel, the `bucket.events` contract version 1. It is tested with the bucket and bucket events conformance suites against an in-memory store and with the bucket suite against a real S3-compatible store.

`s3.buckets(options)` binds Holqa buckets to buckets of an S3-compatible store. It signs requests with AWS Signature Version 4 over `fetch`, so it has no SDK dependency and works with any store that implements the S3 API and SigV4 (for example MinIO, Ceph, Garage or a hosted S3-compatible service).

```ts
import { defineBindings } from "@holqa/bindings";
import { credentialRef } from "@holqa/core";
import { local } from "@holqa/local";
import { rabbitmq } from "@holqa/rabbitmq";
import { s3 } from "@holqa/s3";
import app from "./infra";

export default defineBindings(app, {
  name: "staging",
  defaults: local.platform(),
  kinds: {
    bucket: s3.buckets({
      endpoint: "http://object-store:9000",
      accessKeyId: credentialRef("S3_ACCESS_KEY_ID"),
      secretAccessKey: credentialRef("S3_SECRET_ACCESS_KEY"),
      events: { channel: rabbitmq.eventChannel({ url: credentialRef("EVENTS_URL") }) }
    })
  }
});
```

## Options

| Option | Default | Meaning |
| --- | --- | --- |
| `endpoint` | required | The store's base URL (`http` or `https`). URLs with embedded credentials are rejected. |
| `accessKeyId`, `secretAccessKey` | required | Credential references. Plain strings are rejected. |
| `sessionToken` | none | A credential reference for temporary credentials. |
| `region` | `us-east-1` | The signing region. |
| `forcePathStyle` | `true` | Address buckets as `<endpoint>/<bucket>`; `false` uses `<bucket>.<host>`. |
| `name` | `s3` | The provider's name. |
| `buckets` | none | Store bucket names by Holqa bucket identifier. Names must follow the S3 naming rules. |
| `prefix` | empty | Prepended to Holqa bucket identifiers for buckets that `buckets` does not list. |
| `publicRead` | `false` | Declares that the store's bucket policies allow anonymous reads, so `public-read` buckets can be bound. The provider cannot verify this and never changes policies. |
| `signedUrls` | `true` | Issue presigned URLs, valid for at most 7 days. |
| `events` | none | `{ channel, types? }`: deliver object events from an event channel (below). Without it the provider advertises no events. |
| `timeoutMs` | `30000` | The time limit of one request. |

## Permissions

The provider needs data-plane permissions only: `HeadBucket`, `GetObject`, `PutObject`, `DeleteObject` and `ListBucket` on the configured buckets. It **never creates or deletes buckets, changes policies or configures notifications**. At start it checks every bucket with `HeadBucket` and fails with `HOLQA_BINDING_FAILED` when one is missing.

## Semantics

| Behaviour | How |
| --- | --- |
| Writes | `PutObject` with a signed payload hash. `put` resolves to the object's metadata after the store acknowledged it. |
| Reads | `GetObject` and `HeadObject`; a missing object resolves to `undefined`. |
| Deletion | `HeadObject`, then `DeleteObject`, so `delete` can report whether the object existed. Two concurrent deletes may both report `true`. |
| Listing | `ListObjectsV2` with `encoding-type=url`, pages of at most 1 000 keys, the continuation token as cursor. Order is the store's (UTF-8 byte order on S3-compatible stores). |
| Presigned URLs | Query-string SigV4 with an unsigned payload. A `PUT` URL signs `content-type` when given, and returns it in `headers` for the client to send. |
| Metadata | The content type is stored as the object's `Content-Type`. The writer's trace is stored as user metadata (`x-amz-meta-holqa-trace`). |

## Object events

Object storage and its notifications are usually separate infrastructure: the store publishes S3 event notifications to a message broker, a webhook or a queue. The provider reads them through an **event channel** (`EventChannel` from `@holqa/core`), so it does not depend on any one transport. The implemented channel is `rabbitmq.eventChannel` in `@holqa/rabbitmq`.

| Behaviour | How |
| --- | --- |
| Subscriptions | One per object event handler, named `<bucket>.<handler>`. With `rabbitmq.eventChannel` this is the queue `<queuePrefix><bucket>.<handler>` (default prefix `holqa.events.`), bound by provisioning to the exchange the store publishes to. A missing queue fails with `HOLQA_BINDING_FAILED`. |
| Format | The S3 event notification `Records` format with exactly one record per notification, as S3-compatible stores send. Keys are URL-decoded. |
| Identity | A stable identifier derived from the bucket, key, event name, sequencer and time: redeliveries of one notification have the same identifier. |
| Filtering | Notifications of other buckets, types or prefixes are acknowledged and skipped, so a broader notification rule is harmless. |
| Malformed notifications | Dead-lettered with `HOLQA_PAYLOAD_MALFORMED`. |
| Retries and dead-lettering | The channel's: with `rabbitmq.eventChannel`, delay queues and `<queue>.dead-letter`, as for queues. |
| Lineage | When the store includes user metadata in notifications (MinIO and RustFS do, with or without the `X-Amz-Meta-` prefix), the writer's trace continues in the handler. Stores that do not include it (AWS S3 does not) start a new lineage per event. |
| Delivery | At least once, unordered. |

Configuring the store's notifications (for example MinIO's AMQP target and bucket notification rules) is provisioning, not something the provider does.

## Failures

| Situation | Code |
| --- | --- |
| The store rejects the access key or signature | `HOLQA_BINDING_CREDENTIALS_INVALID` |
| The store cannot be reached, times out or answers 5xx/503 `SlowDown` | `HOLQA_BINDING_UNAVAILABLE` |
| A bound bucket or a notification queue is missing | `HOLQA_BINDING_FAILED` |
| A credential reference is not set | `HOLQA_BINDING_CREDENTIALS_MISSING` |
| Invalid options | `HOLQA_BINDING_CONFIG_INVALID` |

## Testing against a real store

Set `HOLQA_S3_ENDPOINT`, `HOLQA_S3_ACCESS_KEY_ID` and `HOLQA_S3_SECRET_ACCESS_KEY` to run `packages/providers/s3/tests/integration.test.ts`, which creates and removes its own uniquely named buckets. CI runs it against a RustFS service container. Without them the tests are skipped and the in-memory store covers the logic.
